# Kuku Timer: Архитектурный план и бэклог (Blueprint)

## 1. Исчерпывающий план работы приложения (Как это устроено сейчас)

### Ядро (Core Philosophy)
Kuku Timer работает как "умный перехватчик" (интерцептор), который разрывает паттерн бездумного запуска приложений (соцсети, игры).

### Жизненный цикл сессии (Сценарий пользователя)
1. **Запуск ограниченного приложения:** Пользователь тапает на иконку заблокированного приложения (например, Instagram).
2. **Перехват (Interception):** 
   - `KukuAccessibilityService` (основной) отлавливает событие `TYPE_WINDOW_STATE_CHANGED`.
   - Система проверяет, находится ли запущенный пакет в `RESTRICTED_APPS` через `AppPreferences` (Jetpack DataStore).
   - Если пакет заблокирован и сейчас нет активной сессии для него, мгновенно запускается `TimerActivity`.
3. **Режим ожидания ("Варка риса"):**
   - Поверх целевого приложения открывается `TimerActivity` (System Alert Window / `FLAG_ACTIVITY_NEW_TASK`).
   - Запускается отсчет 10 минут.
   - Пользователь блокирует телефон или уходит на рабочий стол.
4. **Уведомление (Точный таймер):**
   - Через `AlarmManager` устанавливается точный будильник (`setExactAndAllowWhileIdle`).
   - Через 10 минут `AlarmReceiver` срабатывает и публикует локальное уведомление: "Ваш рис готов" (Открыто окно возможностей).
5. **Окно возможностей (2 минуты):**
   - Если пользователь кликает по уведомлению или снова открывает то же приложение в течение 2 минут, `TimerActivity` пропускает его (сессия отмечается как разрешенная).
   - Если 2 минуты прошли, сессия сгорает. При следующей попытке придется ждать 10 минут заново.
6. **Сброс (Screen Off):**
   - Если экран устройства выключается (`ACTION_SCREEN_OFF`), все активные разрешенные сессии сбрасываются. При следующем разблокировании телефон снова находится в защищенном состоянии.

### Технический стек
- **UI:** Jetpack Compose (Single Activity + отдельная TimerActivity).
- **Хранилище:** Jetpack DataStore (Preferences).
- **Фон:** Accessibility API (основной) + Foreground Service с UsageStats (резерв).
- **Таймеры:** `AlarmManager` + `BroadcastReceiver`.

## 2. Что ещё нужно сделать (Бэклог и Уязвимости)

На основе анализа архитектуры и манифеста выявлены следующие критические пробелы и точки роста:

### 🔴 Критические
- [x] **Автозагрузка после перезагрузки (Boot Receiver):** Реализован `BootReceiver` с фильтрами `ACTION_BOOT_COMPLETED` и `ACTION_MY_PACKAGE_REPLACED` (см. [ADR-005](../decisions/ADR-005-Boot-Autostart-And-Battery-Exemption.md)).
- [x] **Игнорирование оптимизации батареи (Battery Optimization):** Реализован запрос разрешения `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` и UI-контроль в диалоге настроек.
- [ ] **Защита от удаления и отключения (Strict Mode):** Продвинутые пользователи обойдут Kuku Timer, просто зайдя в настройки и выключив Accessibility Service или удалив приложение. Требуется функционал (Device Admin API или системный перехват настроек), затрудняющий отключение самого блокировщика во время активного таймера.

### 🟡 Средний приоритет (UX и Фичи)
- [x] **Кастомизация интервалов:** Время ожидания и окно доступа вынесены в `AppPreferences` с динамическим UI выбора (5, 10, 15, 20, 30 мин ожидания и 1, 2, 3, 5 мин окна).
- [ ] **Статистика и аналитика "Осознанности":** Записывать в DataStore/Room историю: сколько раз пользователь дождался 10 минут, а сколько раз сдался и не стал открывать приложение. Это даст пользователю мощный фидбек о его прогрессе.
- [ ] **Группировка приложений (Профили):** Сейчас список заблокированных приложений плоский. Было бы полезно создавать профили (например, "Работа" с 09:00 до 18:00 блокирует соцсети, "Вечер" блокирует почту).

### 🟢 Низкий приоритет (Полировка)
- [ ] **Анимации перехода (Shared Element Transitions):** В Compose можно улучшить плавность появления `TimerActivity`.
- [ ] **Виджет на главный экран:** Для быстрого просмотра состояния таймеров.
