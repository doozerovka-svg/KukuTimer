# ADR-004: UI-архитектура на базе Jetpack Compose

## Status
Accepted

## Date
2026-08-28

## Context
Приложение Kuku Timer обладает ярко выраженной эстетикой: дзен, японский минимализм, фокус на плавных анимациях и кастомных UI-элементах (например, ZenBackgrounds).
Необходимо было выбрать стек для построения UI, который обеспечит высокую скорость разработки, легкость создания кастомных графических элементов и предсказуемое управление состоянием экрана (UDF - Unidirectional Data Flow).

## Decision
Весь пользовательский интерфейс построен исключительно на **Jetpack Compose** с применением Material 3. Используется паттерн **Single Activity** (`MainActivity`), а навигация между экранами (Онбординг, Главный экран, Выбор приложений) осуществляется через Compose Navigation. Экран блокировки/таймера вынесен в отдельную `TimerActivity` из соображений жизненного цикла и безопасности перекрытия других приложений (System Alert Window).

## Alternatives Considered

### XML + View System + Fragments
- **Плюсы**: Проверенная временем технология, огромная база готовых решений.
- **Минусы**: Громоздкость кода, сложность создания реактивных UI, рассинхронизация состояния View и данных, сложность реализации плавных анимаций и кастомных компонентов (по сравнению с Compose).
- **Отклонено**: Замедляет разработку и не соответствует современным стандартам Android-разработки (Modern Android Development).

## Consequences
- **Графика**: Создание сложного "Zen" фона и таймеров легко реализуется через `Canvas` API внутри Compose (`ZenBackgrounds.kt`), что позволяет процедурно генерировать частицы и градиенты без тяжелых растровых изображений.
- **Реактивность**: Состояние экранов напрямую привязано к Flow из `DataStore` (например, список заблокированных приложений мгновенно обновляет UI при изменении настроек).
- **Разделение Activity**: Выделение `TimerActivity` в отдельную сущность — компромисс. Несмотря на паттерн Single Activity для основного приложения, экран таймера обязан перекрывать целевые приложения (`FLAG_ACTIVITY_NEW_TASK`, `SYSTEM_ALERT_WINDOW`). Реализовать это поверх стэка задач стороннего приложения проще и надежней через отдельную прозрачную/перекрывающую Activity, чем пытаться встроить Compose-окно напрямую на системном уровне.
