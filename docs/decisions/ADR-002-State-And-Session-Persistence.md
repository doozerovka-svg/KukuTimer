# ADR-002: Хранение состояния сессий и настроек (DataStore)

## Status
Accepted

## Date
2026-08-28

## Context
Приложению необходимо сохранять настройки пользователя, список заблокированных (ограниченных) пакетов приложений, а также состояние онбординга. Структура данных простая (ключ-значение) и не требует сложных реляционных связей.
Кроме того, доступ к этим настройкам должен быть асинхронным и реактивным, чтобы UI (Jetpack Compose) и фоновые сервисы (AccessibilityService) могли получать актуальные данные без блокировки основного потока.

## Decision
Для хранения локальных данных используется **Jetpack DataStore (Preferences)** (`AppPreferences.kt`), который полностью заменяет устаревший `SharedPreferences`.

## Alternatives Considered

### SharedPreferences
- **Плюсы**: Знаком всем Android-разработчикам, прост в использовании.
- **Минусы**: Синхронный API (может блокировать UI-поток), отсутствие встроенной поддержки корутин/Flow, отсутствие безопасности типов, устаревший статус (deprecated Google).
- **Отклонено**: Не соответствует современному стеку Android-разработки.

### Room Database (SQLite)
- **Плюсы**: Мощный инструмент для реляционных данных, строгая типизация, поддержка Flow.
- **Минусы**: Избыточен для хранения простых списков строк (имена пакетов) и булевых флагов. Требует написания DAO, сущностей и миграций, что увеличивает boilerplate-код.
- **Отклонено**: YAGNI (You aren't gonna need it). Наша модель данных слишком проста для реляционной базы.

## Consequences
- **Позитивные**: Идеальная интеграция с Kotlin Coroutines и Flow. Состояние подписок реактивно прокидывается в Compose-экраны и фоновые сервисы. 
- **Позитивные**: Безопасность потоков и транзакционность при записи данных "из коробки".
- **Требования**: Все операции чтения и записи являются асинхронными, что требует аккуратной работы с `runBlocking` (которую следует избегать) или использования `first()` внутри suspend-функций в фоновых сервисах.
